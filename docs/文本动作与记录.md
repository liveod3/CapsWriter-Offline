# 文本动作、光标参考与记录

当前实现移除了客户端和服务端的热词检索、音近/正则强制替换、旧 Python 角色及会话历史。模型自身的词元表、CTC 解码、时间戳对齐仍保留；它们是基本识别能力。去掉替换链路能消除由它造成的误换，但不能保证 ASR 模型自身不再把“苦的”识别成“CUDA”。

## 托盘菜单

菜单采用英文、统一深蓝图标，停留约半秒显示英文说明。暂停与显示控制台的文字会随状态变化。

| 选项 | 行为 |
| --- | --- |
| Show console / Hide console | 显示或隐藏终端窗口；不停止识别 |
| Pause dictation / Resume dictation | 暂停并释放麦克风，或恢复；手动暂停后录音快捷键不会自动恢复。闲置挂起仍允许快捷键唤醒 |
| Copy last result | 复制最近一次结果；取消或失败时可找回原文 |
| LLM actions → All LLM actions: Currently on / off / partly on | 显示当前总状态；全部开启时点击全部关闭，其余状态点击全部开启 |
| LLM actions → Correction: Currently on / off | 显示润色/纠错当前状态，点击切换 |
| LLM actions → Translation: Currently on / off | 显示翻译当前状态，点击切换 |
| Open history | 打开按年/月归档的识别文字目录 |
| Settings | 用记事本编辑客户端配置、Provider 连接或文本预设 |
| Troubleshooting | 重连麦克风、打开诊断日志、复制未经文本动作处理的 ASR 原文 |
| Restart client / Quit | 重启客户端以应用根配置，或退出并释放资源 |

`Context`、`Hotwords`、`Clear memory` 不再存在。LLM actions 顶部为总开关，下方为两个可同时开启的独立开关。例如开启润色时显示 `Correction: Currently on`，关闭时显示 `Correction: Currently off`；文字描述当前状态，点击则切换到相反状态，勾选标记同步变化。总开关全部关闭后，仍可单独开启任意一项；关闭最后一项时总状态自动变为 Currently off。选择后只保存本机 `config_client.py` 的 `llm_enabled`、`llm_correction_enabled` 和 `llm_translation_enabled`，下次请求立即生效，重启后保留。保存成功显示 `LLM settings saved.`，失败保留原状态。若编辑器中已打开该文件，重新从磁盘加载后再核对这三个字段。正在处理的请求沿用开始时的开关快照；需要取消时仍可按 `llm_stop_key`，默认 Esc。重连麦克风需要先恢复听写，并在录音结束后使用。

“全部开启”表示允许使用两种能力，每句话仍只执行一个预设。推荐普通听写使用润色，明确说“翻译…”时直接翻译；不会并行输出两份文字，也不会默认串联润色与翻译。每个预设通过 `provider` 指定一个服务及模型，不自动轮询其他服务。高级配置 `llm_default_preset` 决定普通听写的默认动作；已有自定义值保持不变。关闭某项能力后，对应的默认预设和显式口令都会停用，原文中的口令不会被吞掉。

如果旧配置默认选择 `translate`，但当前翻译关闭、润色开启，普通听写回退到润色，避免开着润色却完全不处理。不会自动回退到翻译；`llm_default_preset = None` 仍表示只接受显式口令。这个回退不改写本机的默认预设值。

## 转写与 LLM 等待提示

录音结束后立即显示 `Transcribing…`，覆盖尾部音频排队/发送、本地 ASR 处理及等待最终结果的时间。收到最终转写后进入 `Preparing text…`；需要执行 LLM 时，在读取预设之前显示 `Preparing LLM…`，发起请求时切换为 `Waiting for LLM…`。这些处理状态持续显示，不再在 2.5 秒后自动消失。无需 LLM 的转写直接进入输出。

完成、取消、发送失败、断线和退出会清理对应状态。连续录音时优先显示较新的待处理任务，较早任务完成不会清除较新任务的提示；较新任务完成后恢复仍在等待的旧任务。短通知暂时覆盖处理提示，通知结束后恢复当前阶段。所有状态窗操作通过现有 Tk 管理器队列执行，调用方不等待 Tk root 就绪。真实桌面的焦点、多屏与 DPI 效果仍需实机回归。

诊断日志中的 `Dictation stage` / `Dictation stage ended` 记录阶段耗时；`Transcribing…` 的耗时包含客户端尾音频处理与等待结果，并非纯模型推理时间。`LLM request started` 记录请求编号和准备耗时，完成/失败日志记录同一请求编号及总耗时，可据此定位等待发生在哪个阶段。本次 Python 代码改动需要重启客户端生效。

## LLM 失败诊断

开启 `save_diagnostic_logs` 且日志级别允许 WARNING 时，失败记录写入 `logs/client_latest.log` 和 `logs/diagnostics/YYYY/MM/client_*.log`。阶段与成功耗时使用 INFO；当前本机 DEBUG 设置会包含这些记录。

日志包含请求编号、失败阶段、异常类型、分类、耗时和受控原因说明：

- 网络：区分连接、读取、发送、连接池超时以及总请求超时；有底层异常信息时附带系统错误号或 TLS 证书验证失败原因。
- 服务端：保留 HTTP 状态码，解析已知的 `error.status`、`error.code`、`details[].reason`、数字秒形式的 `Retry-After` 和 `retryDelay`。例如 429 可以进一步报告配额/限流及建议等待秒数，400/403 可以进一步指出 API Key 无效或因泄露被禁用。
- 生成结果：检查 OpenAI 兼容接口的 `finish_reason`、拒绝、工具调用及空输出；若响应透传 Gemini 的 `promptFeedback.blockReason` / `candidates[].finishReason`，也解析其失败原因。达到 token 上限的部分输出按失败处理，保留转写原文。
- 配置与格式：区分本机配置加载失败、缺少 Key、无效 JSON、异常响应结构和响应超限。失败提示显示可理解的原因；取消不记作错误，也不自动重试。

Google 的[错误格式规范](https://google.aip.dev/193)定义了 JSON 错误中的 code、status 和 details；Gemini 的[生成结果文档](https://ai.google.dev/api/generate-content#FinishReason)说明了内容阻止和生成结束原因。当前客户端仍使用 [Gemini 的 OpenAI 兼容接口](https://ai.google.dev/gemini-api/docs/openai)，实际可记录的字段取决于该接口或代理返回的数据，不假定原生 Gemini 字段一定存在。

为防止服务端把请求文本或凭据回显到日志，不原样写入 `error.message`、`finishMessage` 或整个响应；从已知错误码和明确错误措辞提取固定的原因说明。未知原因标记为 `unknown` 并保留 HTTP 状态/错误分类，不能据此声称已保存服务端全部原始详情。

## 每次读取光标附近文本

在根目录 `config_client.py` 的 `ClientConfig` 中配置：

```python
caret_context_enabled = False
caret_context_before_chars = 800
caret_context_after_chars = 200
```

开启后，每次开始听写，通过 Windows UI Automation 读取当前输入位置之前/之后的有限文字；单次上限分别为 2000/1000 字符。同一录音的所有分片复用这次快照，下次录音重新读取。不会轮询编辑内容、操作剪贴板或模拟 Ctrl+A/Ctrl+C。

读取在可终止的隔离进程中执行，最多等待约 1.5 秒；不阻塞音频设备回调。密码框、存在选区、控件不支持 TextPattern2、焦点变化或超时，都按没有上下文继续。不同应用暴露的辅助功能接口不同，因此无法保证任意输入框可用；管理员权限不一致也可能无法读取。

参考文本通过现有 ASR `context` 字段发往配置的服务端：Qwen3-ASR/Fun-ASR 使用参考提示，SenseVoice/Paraformer 不使用。它是辅助判断语义的数据，不是风格指令，也不会被作为会话历史保存。若 ASR 服务端在另一台机器，开启此功能也会发送这段参考文本。

LLM 默认不接收参考文本。只有该预设同时设置 `use_caret_context = true` 才会附带；它仍受客户端读取总开关控制。关闭 LLM 不会关闭独立的 ASR 光标参考。

## Provider 与提示词预设

`LLM/providers.template.toml` 是进入 Git 的公开模板；`LLM/providers.toml` 是 Git 忽略的本机连接与凭据配置。缺少本机文件时只读模板，首次从托盘编辑 Provider 时创建本机副本，已有文件不会被覆盖。`LLM/presets.toml` 负责提示词、稳定 ID、英文显示名、触发口令、生成参数和是否附带光标参考。修改 TOML 后下次请求生效，无需文件监控或重启；手动编辑根客户端配置需要重启，托盘 LLM actions 切换则立即生效。

默认附带 `correct_asr` 和 `translate` 两个预设。纠错会结合本次转写的整句话、前后句及话题，主动修正有语义依据的同音/近音识别错误，删除无意义的语气词、口头填充词和口吃重复，并按句法整理顿号、逗号与断句。保留有意义的指代、强调、疑问语气和原意，只做小幅局部调整，不扩写、不回答内容中的问题，也不凭发音强行替换技术术语或专名；有歧义时保留原词。例如，提示词引导将“请把这份合同发到我的油箱里”整理为“请把这份合同发到我的邮箱里。”，将“呃需要苹果，香蕉，橙子”整理为“需要苹果、香蕉、橙子。”，实际效果取决于所用模型。

纠错仍要求明确数值使用半角阿拉伯数字，例如“两百三十个”→“230个”、“三点一四”→“3.14”、“百分之十五”→“15%”。保留单位、精度及编号前导零；固定词语、成语、专名中的数字不机械替换，不确定数量不猜测，日期暂保留原格式。这里的上下文默认指本次转写内部的前后文；仅在光标参考开关启用且预设允许时，额外参考周围已有文字，不读取历史会话。翻译默认译成英文，可以修改提示词中的目标语言。

```python
llm_enabled = False                  # 总开关：关闭时不调用任何 Provider
llm_correction_enabled = True        # 润色能力开关，受总开关约束
llm_translation_enabled = True       # 翻译能力开关，受总开关约束
llm_default_preset = 'correct_asr'    # 自动处理时最多一个预设
llm_config_dir = 'LLM'
```

下表假定两个独立能力开关均开启；旧配置缺少这两个字段时也按此处理。关闭总开关始终不请求 LLM。

| 配置 | 普通听写 | 明确语音口令触发 |
| --- | --- | --- |
| `llm_enabled = False` | 原识别流程 | 不调用 LLM |
| `True`，默认 `'correct_asr'` | 自动纠错一次 | 仅执行指定预设，不先纠错再翻译 |
| `True`，默认 `'translate'` | 自动翻译一次 | 仅执行指定预设 |
| `True`，默认 `None` | 不自动处理 | 执行指定预设一次 |

不能配置多个默认预设或数组。可以定义多个预设，用各自的 `triggers` 选择；显示名不用于匹配。默认翻译口令是“翻译”及 `Translate:`，例如“翻译：今天有点冷”。匹配发生在开头，口令被去除后剩余内容作为输入；有多个匹配时采用最长口令。若不需要口令，设为 `triggers = []`。手动配置 `None` 或自定义默认预设仍受支持；能力开关与默认路由是两个独立设置，菜单不会重写默认预设。当前独立开关对应内置 `correct_asr` 和 `translate`，自定义预设受 LLM 总开关控制。

每次请求只有系统提示词和当前输入两条消息，没有上下文对话、历史文件加载、选区或剪贴板采集。整个结果返回后才输出；窗口发生变化时不自动上屏，可用 Copy last result 取回。取消不会自动上屏；配置、认证、超时或网络失败保留待处理原文，无自动重试。`Copy original transcription` 始终提供最初 ASR 结果。

当前默认预设使用 Gemini 3.5 Flash-Lite。本机 `config_client.py` 已开启 `llm_enabled`，纠错与翻译均路由到 `gemini`；只需在 **本机 `LLM/providers.toml`** 的 `[providers.gemini]` 下填写 `api_key`，重启客户端加载启用状态。以后只修改 Key/TOML 时，下次请求即生效。发行模板中的 LLM 总开关仍默认关闭，新安装需自行开启。

如果纠错和翻译都提示 `API key missing`，从托盘 `Settings → Provider connections…` 打开本机文件并填写 Key。模板中的空值是占位配置；不要把真实 Key 写入模板。若配置了 `api_key_env`，它优先于文件中的 Key：需要设置对应环境变量并重启客户端，让新进程读取环境。

```toml
[providers.gemini]
kind = "openai"
base_url = "https://generativelanguage.googleapis.com/v1beta/openai"
model = "gemini-3.5-flash-lite"
api_key = "" # 只在本机 providers.toml 填写 Key，禁止填写模板
timeout = 30
```

上例的 `kind = "openai"` 是兼容协议名称，实际请求发给 Google。模型 ID 来自 [Google 模型文档](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite)，基础地址与 Bearer 认证来自 [Google 兼容接口文档](https://ai.google.dev/gemini-api/docs/openai)。Key 在 [Google AI Studio](https://aistudio.google.com/apikey) 获取，详见[官方 Key 使用说明](https://ai.google.dev/gemini-api/docs/api-key)。客户端在基础地址后追加 `/chat/completions`，不要重复填写该路径。

可以直接填写本机 `api_key`；也可设置 `api_key_env = "GEMINI_API_KEY"`，使用该环境变量。显式指定环境变量后优先使用它，变量为空会报配置错误，不回退到文件中的 Key。空的 `api_key` 在发起网络请求前被拒绝，失败时保留原始转写；不会自动联网测试或下载模型。

模板不能写真实凭据，`providers.toml` 已被 `.gitignore` 排除。两份打包 spec 只复制公开模板和预设，发行包内的 `providers.toml` 来自空 Key 模板，不链接工作区的 `LLM` 目录。若旧打包目录残留 LLM junction，复制步骤会拒绝穿过它覆写本机配置；打包检查也拒绝包含非空 `api_key` 的模板。

模板仍提供 `local` Ollama 连接示例；改用本地模型时，将预设的 `provider` 改成 `"local"`，并配置已有模型名与本机地址。

调用时状态提示显示动作、模型和 Local/Remote，停留 2.5 秒（原为 5 秒）。Remote 表示地址不是常见 loopback 地址，可能是局域网或云端。`llm_enabled=False` 保证此文本服务不联网，但不控制 ASR 服务连接或 UDP；项目尚无覆盖所有组件的严格离线总开关。

## 文字记录与音频独立保存

只想保存识别记录、不保存 MP3/WAV，可以使用：

```python
save_transcripts = True
transcript_dir = 'logs/transcripts'
transcript_save_original = False
save_audio = False
save_llm_records = False
```

| 数据 | 控制项 | 位置及说明 |
| --- | --- | --- |
| 听写文字 | `save_transcripts` | `logs/transcripts/YYYY/MM/DD.md`，当天追加；保存最终文本 |
| ASR 原文对照 | `transcript_save_original` | 仅在启用文字记录且原文不同于最终结果时附加 |
| 麦克风音频 | `save_audio` | 保留原有 `YYYY/MM/assets/`；有 FFmpeg 保存 MP3，无 FFmpeg 或启动失败降级 WAV |
| 文本动作记录 | `save_llm_records` | `logs/text-actions/YYYY/MM/DD.md`，保存成功动作的输入与输出，不保存 Prompt、密钥或参考文本；不会用于后续请求 |
| 诊断日志 | `save_diagnostic_logs`、`log_level` | `logs/client_latest.log` 保留便捷排障入口，同时归档到 `logs/diagnostics/YYYY/MM/` |
| 文件转录任务日志 | `file_separate_log` | `logs/transcribe/YYYY/MM/`，与麦克风文字记录独立 |

诊断归档按日期和进程分文件，单文件约 10 MiB、最多 5 个滚动备份。`diagnostic_log_retention_days = 30` 在初始化/跨日时清理过期诊断归档；`0` 表示不自动清理。此策略不删除文字、音频或文本动作记录，后面三类目前由用户手动管理。旧模块的诊断日志仍可能含识别内容，文字记录并不是唯一敏感数据来源。

## 旧配置迁移

本次工作区的旧角色与词表已备份至 Git 忽略的 `.cache/legacy-feature-backup-0914/`，没有清理原有音频、日记或 logs。其他安装升级前应先自行备份旧配置及 `LLM/*.py`。

旧 `context`、`hot*`、服务端词表参数不再被运行链路读取，旧角色 Python 文件也不再执行。把需要保留的模型地址、模型名手动迁入 Provider，把提示词迁入 Preset；旧内联密钥改为环境变量或仅保存在被忽略的本机 Provider TOML，旧选区、历史、输出方式字段不迁移。旧日志不会自动搬移或转换。

缺少新字段的旧客户端配置有兼容默认值：光标参考关闭，文字与文本动作归档不会因缺字段自行启用，诊断保留原有行为；已有 `llm_enabled=True` 时，新预设目录需要同步准备。当前工作区为 Gemini 配置开启了 `llm_enabled=True`，`save_audio=False` 保持不变；光标参考仍默认关闭。
