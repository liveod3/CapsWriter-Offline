# 转录文件与重建字幕

将音视频文件转为文本、SRT 和时间戳 JSON。文件转录需要运行中的服务端与 PATH 中可用的 FFmpeg；字幕重建只使用已有 TXT/JSON，不需要模型、服务端或麦克风。

下列命令在应用根目录执行，`python` 指已准备的项目解释器。环境准备见[开发环境](../development/setup.md)。

## 使用独立转写窗口

运行 `./start.ps1 -Transcribe` 打开窗口；需要同时启动服务端时使用 `./start.ps1 -Server -Transcribe`，等待模型就绪后再开始。

从文件管理器拖入音视频文件或文件夹，出现释放提示后松开鼠标；也可以点击“选择…”打开 Windows 原生文件选择框，支持一次选择多个音视频文件。添加整个文件夹时，直接从文件管理器拖入窗口即可，默认也会扫描子文件夹。复制文件、文件夹及其绝对路径后，也可以在窗口中按 `Ctrl+V`。文件夹在后台扫描，按 `file_media_extensions` 筛选媒体并去除重复路径；`file_scan_recursive` 默认为开启，会包含子文件夹。队列最多保留 200 个文件，一次扫描最多检查 20,000 个目录条目、深入 32 层，并跳过目录链接和联接点。遇到限制或无法读取的项目，窗口会提示。窗口每次打开时默认只勾选 SRT 字幕，其他格式可按需开启。再次选择文件会追加到原队列末尾，已有路径会去重；取消选择不改变队列。选择导出格式后开始，运行期间加入的新文件留待下一批处理，或暂停后点击继续时处理。

左侧是文件队列，鼠标滚轮每格按一项平滑移动，触控板保留连续滚动。右侧依次是导出选项、处理状态和可收起的日志。没有正在处理的文件时，状态卡只显示空闲提示，隐藏进度条和处理指标；已完成文件的结果与详情保留在队列和日志中。

按住左键拖拽队列项可调整处理顺序；支持 `Ctrl` 多选、`Shift` 连选和 `Ctrl+A` 全选。右键菜单提供上移、下移、置顶、置底、按文件名升降序、打开文件夹、移除选中项。也可以按 `Alt+↑` / `Alt+↓` 移动选中项，按 `Delete` 从队列移除；这些操作不会删除磁盘上的文件。开始转写后，当前批次按队列顺序执行，排序、移除和清空队列暂时锁定，避免显示顺序与执行顺序不一致；文件夹扫描期间也暂时禁用队列修改。

队列右上角的 **Select mode／选择模式** 会在每行最左侧显示方形选框。点击选框或文件行可切换选择，不需要按住 Ctrl；按住选框或文件行后拖动会调整从起点到当前位置的连续选择范围；回划时，退出范围的项目恢复拖动前的状态。既可从空框开始勾选，也可从已选项开始取消，并在同一次拖动中反复调整。划到列表顶部或底部会自动滚动；松开、切换窗口、关闭模式或重建列表时结束划选。空格键也可切换当前行。点击 **Done／完成勾选** 返回原来的 Ctrl／Shift 选择及拖拽排序，已有选择保留。勾选用于移除、移动等队列操作，开始转写仍处理全部未完成文件。底部只保留红色 **Clear queue／清空队列** 和打开文件夹。清空会先确认全部文件数量，默认取消，仅清除队列记录，不删除磁盘上的原文件或结果。部分移除通过右键菜单完成，菜单会明确显示“从队列移除 N 个文件”，也可使用 Delete 键。

多选与单选共用右键菜单，多选时移动和移除命令会显示文件数量。上移／下移每次移动一位，连续选中项作为一组，不连续的组分别移动；到达边界的组保持原位，其他组仍可移动。置顶／置底会将选中项按原相对顺序集中放到顶部／底部。暂停时，已完成项仍固定在原位置，移动只作用于未完成项。

**Open folder／打开文件夹** 打开当前文件所在目录，转写结果默认保存在该目录。已移除单独的打开结果按钮与菜单项。列表左下角不再重复显示“等待转写”等普通状态，只在有输出或错误时显示详情；结果详情的悬停提示保留全部实际输出路径。

转写期间点击**当前文件完成后暂停**，当前文件会正常处理并保存结果，然后暂停队列；等待期间可以取消暂停请求。暂停后，可以拖拽或通过右键菜单调整未完成文件的顺序，已完成项保持原位。点击**继续剩余文件**后按新的顺序处理未完成项，跳过已完成项。若当前已经是最后一个文件且没有其他未完成项，处理结束后直接显示队列完成。

需要立即中断时，点击**终止当前文件**，确认框会说明继续时需要从头转写该文件，默认选择继续当前处理。只有确认**放弃进度并暂停**后，才会取消当前文件，等待后台资源释放，然后保持暂停。可以将被中断文件移到后面再继续。已完成文件和已经写入磁盘的结果不会删除。如果文件在确认期间恰好完成，会保留其完成状态，并等待确认结果后再决定是否启动下一文件。这些操作不会保存文件内检查点，也不会持久保存队列。

窗口与终端共用进度、计时、平均速度和预计剩余时间的计算方式，时长按相同规则四舍五入到秒。单文件计时从媒体时长探测结束、开始转写时起。每收到一个推进已处理音频位置的分段结果，记录该块音频时长与距上次结果的实际间隔；第一块从转写开始计时。上一块速度为该块音频时长除以该间隔，平均速度为所有已完成块的音频时长之和除以这些间隔之和。这些间隔包含上传、排队和识别，不是纯 GPU 耗时。等待下一块时速度保持不变，已用时间继续计时，预计剩余时间继续倒计时。单文件最终汇总使用实际音频总时长除以实际转写耗时；批次汇总覆盖整个批次执行。

窗口用分块图形显示识别进度：实心块表示已完成，描边块表示当前等待完成的块，浅色块表示剩余块；块宽与音频时长成比例，例如 30 秒块是 60 秒块的一半宽，重叠音频不重复计入。识别前依据探测时长估算尾块，结束后用实际确认的音频时长校正；未知时长时暂按标准块宽显示。不会模拟块内进度，也不再显示跳动的百分比。状态卡依次显示文件名、当前活动、合并的总计／已处理／剩余音频时长、已用时与预计剩余、平均速度与上一块速度，最后显示分块图。上一块的具体音频时长和用时可悬停速度行查看。状态卡不再显示连接地址和无进度超时提示，实际故障仍会报告。总块数根据探测时长及分段设置预估，结束后以实际结果为准；未知时长时只显示已完成块数。长文件仅显示当前块附近的一段，悬停可查看显示范围。默认 60 秒分段与 4 秒重叠不变，最后一块的长度可能不同。全部块完成后仍可能正在保存或收尾；只有结果保存且后台任务正常结束，队列才显示完成。分块之间的正常等待不再产生警告日志；实际达到配置的无进展超时或发生连接失败时，仍会给出具体原因。选择队列中的文件可查看失败建议，成功后可打开文件夹查看本次实际生成的结果。

进度区下方的事件日志实时追加带时间戳的文件开始、处理阶段、已确认进度、单文件完成时的音频时长／耗时／速度、实际输出路径、批次汇总，以及取消和失败信息。长路径和消息随日志区宽度自动换行。不同颜色区分普通信息、进度、成功、警告、错误和输出路径；已有同名结果时，自动编号避让的提示会突出显示为警告。

点击日志右上角的箭头可收起或展开，收起后保留简洁的标题栏，期间仍继续接收记录。跟随与清空操作位于日志底部。默认跟随最新记录；向上滚动会暂停跟随，重新勾选跟随复选框可回到底部。清空日志需要确认，默认选择不清空；确认后只清除当前显示，不删除转写结果。窗口最多保留最近 1,000 个文本段落，每段最多 2,000 字符，自动换行不另计段落。记录关闭后不保留，不会自动另建日志文件；其中包含所选文件路径和处理指标，不显示识别正文，也不会把路径或消息中的 HTML 当作格式执行。原有客户端诊断记录仍由各自的配置开关控制。

右上角带调节图标的 **Settings / 设置** 提供以下本次窗口配置，不修改磁盘上的客户端配置，也不改变正在运行的批次。页面按识别、音频分段、超时和连接分组；数值支持直接输入或点击两侧减号、加号调整。**还原默认值**先填回程序默认参数，点击**应用**才生效，点击**取消**保留原设置。默认分段长度仍为 60 秒、重叠为 4 秒。

| 配置 | 作用 |
| --- | --- |
| 识别语言 | 向 ASR 传递语言选择，支持情况取决于模型 |
| 分段长度、分段重叠 | 控制音频分片及上下文；窗口校验消息大小和重叠约束 |
| 最多待处理音频块 | 限制发送窗口；过小而不能容纳分段及重叠时拒绝开始 |
| 解码与发送超时 | 单次 I/O 的等待上限；GUI 连接服务端最多等待 15 秒 |
| 无识别进展超时 | 连续没有服务端确认进度时的等待上限，不是文件总时长 |

日常转写通常只需选择输入文件和输出格式，上述高级参数可保留默认值。服务地址可在设置中查看；连接地址、TLS 和认证沿用客户端配置。模型、标点、数字规范化和强制对齐仍由服务端管理；文件转写不调用听写的 LLM 文本处理。输出格式在主窗口选择，结果保存到原文件所在文件夹。关闭窗口会结束当前后台文件任务，保留已经写入的结果；关闭窗口后队列不持久保存。

## 转录一个文件

1. 启动服务端并等待模型就绪。
2. 执行转录：

   ```powershell
   python start_client.py transcribe --format srt,txt,json "D:\Videos\lecture.mp4"
   ```

3. 等待终端显示完成汇总，检查媒体文件旁的输出。

通过 Conda 运行并需要实时进度时，使用：

```powershell
conda run --no-capture-output -n capswriter python -u start_client.py transcribe "D:\Videos\lecture.mp4"
```

`--no-capture-output` 避免 Conda 捕获输出，`-u` 关闭 Python 输出缓冲。

## 批量转录

一次可以传入多个文件或目录：

```powershell
python start_client.py transcribe "D:\Videos\a.mp3" "D:\Videos\b.mp4" "D:\Courses"
python start_client.py transcribe --recursive "D:\Videos"
python start_client.py transcribe --no-recursive "D:\Videos"
```

目录扫描按路径排序并去重，只纳入 `file_media_extensions` 中的扩展名。未传递扫描选项时，使用 `file_scan_recursive`。直接指定的媒体文件仍需 FFmpeg 支持其格式。

发行包支持把媒体文件或目录拖到 `start_client.exe`；裸路径会转换为转录命令，并使用配置默认值。源码也保留裸路径兼容入口。

## 选择输出格式

| 格式 | 内容 | 模板默认 |
| --- | --- | --- |
| `srt` | 带时间轴的字幕 | 开启 |
| `txt` | 按标点分行的文本 | 开启 |
| `json` | 识别文本、tokens 与时间戳 | 开启 |
| `merge` | 未分行的 `.merge.txt` | 关闭 |

`--format` 或 `-f` 完整覆盖本次输出集合。例如，`--format srt,txt` 只保存两种格式，也可重复使用 `-f srt -f txt`。这些参数不写回配置，不跳过 ASR 或文件对齐。

结果保存在输入文件旁。若任一启用格式已有同名文件，程序会为整组结果选择相同编号，例如 `lecture (2).srt`、`lecture (2).txt`。检查完成提示中的实际路径；输出失败时，不要只凭目录里已有同名文件判断本次成功。

文件任务写入同一份客户端诊断，完成汇总显示当前文件路径；不再创建 `transcribe` 副本。`file_separate_log` 是已停用的兼容字段。诊断开关、正文副本和阅读方法见[日志指南](logs-and-records.md)。

## 校对后重建 SRT

1. 编辑生成的 TXT，修改错字并调整分行。
2. 保留同一段音频的原始时间戳 JSON。
3. 指定两个文件：

   ```powershell
   python start_client.py rebuild-srt --text "edited.txt" --json "timestamps.json"
   ```

程序按已有时间戳对齐新文本，不会重新识别音频。TXT 和 JSON 可以不同名，但两者都必须提供。打包版可同时拖入恰好一个 TXT 和一个 JSON。已有 SRT 使用新编号避让。

## 检查时间轴和资源限制

时间戳质量取决于模型与对齐结果。Qwen ASR 不直接产生 token 时间戳，文件任务通常需要 ForcedAligner。当前结果尚未完整标注时间戳来源/质量；生成了 SRT 不等于时间轴已经准确测量。交付字幕前试听并检查分句边界。

转录并非无条件不限时长。模板限制单任务音频总量、任务持续时间、连接任务数和队列容量；默认单任务音频上限为四小时，任务持续时间上限为六小时，另有 I/O 和无进度超时。配置及限制以[服务端模板](../../config_templates/config_server_template.py)为准。

多个文件任务和麦克风可以共享服务端，各连接/任务相互隔离。当前只有一个 ASR Worker，任务轮转共享推理资源；文件分片处理期间听写可能等待。

## 相关设置

分片长度与重叠由 `file_seg_duration`、`file_seg_overlap` 控制，当前模板保留 60 秒分段、4 秒重叠；已有本地配置以实际值为准。进度按已识别分段确认，60 秒指音频分段长度，不保证每秒更新一次；当前模型接口不提供分段内部逐秒确认的识别位置。速度显示的平滑不会改变分段长度或生成额外的已处理进度。不要把较大分片简单等同于更高效率，它也影响延迟、内存和引擎限制。

输出默认值是 `file_save_srt`、`file_save_txt`、`file_save_json` 和 `file_save_merge`。

查看完整参数：

```powershell
python start_client.py transcribe --help
python start_client.py rebuild-srt --help
```
